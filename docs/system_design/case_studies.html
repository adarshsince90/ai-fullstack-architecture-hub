TinyURL Architecture & Base62 Encoding

Core Requirements: Given a long URL (e.g., https://example.com/long/path), generate a unique 7-character alias (e.g., tiny.url/aB3x9Z). When accessed, issue an HTTP 301/302 redirect.

  • Base62 Encoding: Uses [a-z, A-Z, 0-9] ($62$ characters). A 7-character string yields $62^7 \approx 3.5 \text{ Trillion}$ unique URLs.
  • Key Generation Service (KGS): Pre-generates random 7-character keys in memory to avoid key collisions during high-concurrent writes.
CLIENT REQUEST ──► LOAD BALANCER (Nginx) ──► API GATEWAY (Rate Limiter) │ ┌──────────────────────────────────┴──────────────────────────────────┐ ▼ (Read: Redirect) ▼ (Write: Shorten URL) REDIS DISTRIBUTED CACHE ──(Cache Miss)──► RDBMS READ REPLICAS KEY GENERATION SVC (KGS) │ │ (Return HTTP 301) Fetch Pre-generated Key & Write to Primary DB

Database Schema (NoSQL / SQL)

Table: URL_Mapping {
  short_key   VARCHAR(7) PRIMARY KEY, -- e.g. "aB3x9Z"
  original_url TEXT NOT NULL,
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  user_id     UUID NULL,
  expires_at  TIMESTAMP NULL
}
