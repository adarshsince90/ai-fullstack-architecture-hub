1. Rate Limiting Algorithm Comparison Matrix

Rate limiters protect API gateways from DDoS, brute-force attacks, and cascading service outages.

Algorithm How It Works Pros Cons & Edge Anomalies Best Use Case
1. Token Bucket ⭐ Tokens refilled at rate $R$ up to max capacity $C$. Each request consumes 1 token. Allows controlled traffic bursts up to bucket capacity; memory-efficient ($O(1)$ state: count + last refill time). Parameters $R$ and $C$ require careful tuning. General API Gateways (AWS API Gateway, Stripe API, Envoy).
2. Leaky Bucket Requests enter a FIFO queue and are processed at a strictly fixed constant rate. Smooths out traffic spikes into perfectly steady downstream flow. Bursts fill the queue rapidly, causing delayed responses or dropped packets. E-commerce order checkout queues, payment processor rate levelers.
3. Fixed Window Counter Counts requests per fixed time block (e.g., 00:00-00:59). Resets to 0 at minute boundary. Extremely simple; $O(1)$ memory. Boundary Spike Hazard: $2\times$ allowed traffic can pass if sent at 00:59 and 01:01. Low-security background jobs, hourly quota resets.
4. Sliding Window Log Stores sorted timestamps of all requests in Redis Sorted Set (`ZSET`). Discards timestamps older than window. 100% precision with zero boundary spikes. High memory usage ($O(\text{Requests})$ storage per user). Vulnerable to memory saturation during DDoS. High-security financial transactions & login attempt limits.
5. Sliding Window Counter ⭐ Approximates sliding window using formula: $\text{Count} = \text{CurrentWindow} + \text{PrevWindow} \times (1 - \text{OverlapWeight})$. Zero boundary spikes, negligible memory ($O(1)$ with only 2 counters). Minor mathematical approximation error ($\approx 0.05\%$). Cloudflare edge rate limiting, high-throughput microservice meshes.

2. L4 vs L7 Load Balancers & Edge Gateway Routing

Understanding the OSI stack distinction between Layer 4 (Transport) and Layer 7 (Application) routing.

⚡ Layer 4 Load Balancing (Transport Layer: TCP/UDP)

• Mechanism: Inspects only IP address and TCP/UDP port without decrypting TLS or reading HTTP headers.
• Routing Algorithms: Round Robin, Weighted Least Connections, IP Hash, Maglev Consistent Hashing.
• Performance: Extreme throughput ($>1\text{M packets/sec}$ with kernel bypass DPDK / eBPF) with negligible CPU overhead.
• Examples: AWS Network Load Balancer (NLB), HAProxy (TCP mode), Linux LVS, Google Maglev.

🌐 Layer 7 Load Balancing (Application Layer: HTTP/gRPC/WebSocket)

• Mechanism: Terminates TLS, parses full HTTP payload, headers, cookies, URL paths, and gRPC method names.
• Capabilities: Path-based routing (`/api/v1/orders` vs `/api/v1/users`), Sticky sessions (Session cookies), Header injection, JWT verification, Canary releases.
• Performance: Higher latency & CPU load due to TLS termination and header parsing.
• Examples: AWS Application Load Balancer (ALB), Nginx, Envoy Proxy, Traefik.

4. Interactive Consistent Hashing Ring with Virtual Nodes

In Consistent Hashing, keys and servers are mapped to a $360^\circ$ hash ring. Adding or removing a server node only remaps keys belonging to the immediate clockwise neighbor, minimizing cache re-shuffling from $100\%$ to $1/N$.
